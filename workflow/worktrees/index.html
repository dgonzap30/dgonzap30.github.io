The workflow / Part 2 of 7

One checkout per branch, in one predictable place.

Agents and people edit the same repositories at the same time. A single checkout makes that a queue; a worktree per branch makes it parallel, and a fixed location makes it findable.

From ~/.claude/rules/project-inventory.md · A rule file and a git alias · Verified 2026-09-11

A shared checkout serialises everything.

With one working tree, two pieces of work in the same repository cannot proceed at once. Switching branches disturbs whatever else is mid-edit, and uncommitted work becomes a reason not to start the next thing.

That cost is invisible with one person and one task. It becomes the dominant cost the moment several sessions are working across the same repositories.

Failure mode The tell is a stash used as a scheduling primitive.

Worktrees live in exactly two places.

The rule is written down rather than remembered, in ~/.claude/rules/project-inventory.md, and it is short enough to quote in full:

  • Manual worktrees go in ~/dev/.worktrees/<repo>/<branch-slug>/ and nowhere else.
  • Harness-created worktrees go in <repo>/.claude/worktrees/.
  • Never ~/dev/<repo>-<branch>, and never a new *-worktrees/ directory.
Why a fixed path A predictable location is what makes an automated inventory possible at all.

The rule is a git alias, not a habit.

git wt <branch>, run from inside a repository, derives the repository name from the toplevel, slugifies the branch by replacing slashes with hyphens, creates the parent directory, and adds the worktree at the sanctioned path. It prints where it put it.

Nothing about the rule depends on anyone recalling it under pressure, which is the only way a layout convention survives contact with a busy week.

Verify git config --get alias.wt

At ninety-nine worktrees the layout is the feature.

There are currently 99 worktrees under ~/dev/.worktrees/, across repositories including an editor, a session catalog, a film app, a dotfiles kit and a media pipeline.

None of them are lost, because there is exactly one place they can be. Finding every branch in flight is a directory listing, not an investigation.

Count find ~/dev/.worktrees -maxdepth 2 -mindepth 2 -type d | wc -l → 99 on 2026-09-11.

Consolidation is part of the rule.

Three competing worktree roots existed before this rule and were folded into one on 2026-08-28. The move is recorded in ~/dev/MOVES.md rather than discovered later by a broken symlink.

A layout rule written after the sprawl is worth less than the migration that removes the sprawl. Both are required.

Recovery Every relocation is logged, newest first, so a stale path in an old config resolves in one lookup.

Cheap to make, therefore cheap to discard.

A worktree that costs one command to create is one you delete without ceremony when the branch merges. The discipline that matters is not creating fewer of them; it is never leaving one in a place the inventory cannot see.

Unregistered directories are surfaced daily rather than found by accident, which keeps the count honest in both directions.

Boundary This page describes a personal layout policy. Nothing here is a claim about anyone else's repositories.
